# 加州海岸晚霞预报

[English](README.md) · **中文**

**线上地址：https://runwang06.github.io/ca-sunset/**

覆盖加州整条海岸（58 个城市、海滩和观景点，从 Crescent City 到 Coronado）的日落与火烧云预测。只看日落，回答三个问题：**今天/明天哪里值得去、几点到、为什么**。

纯静态网站：没有后端，也不需要 API key。匿名访问统计发送到 GoatCounter（见下文）。气象数据由 GitHub Actions 每小时预先获取一次，和网站一起部署到 GitHub Pages（见下文“数据怎么到达浏览器”）。

## 本地运行

```bash
python3 serve.py
```

然后打开 http://127.0.0.1:8765 。测试页在 http://127.0.0.1:8765/tests.html ，页面标题会显示 PASS 或 FAIL。

`serve.py` 是一个关闭了缓存的 `http.server`，方便调试，无论从哪个目录启动都只提供它所在的文件夹。网页用的是 ES modules，不能直接用 `file://` 打开。

本地没有 `data.json` 时，网页会直接调用 Open-Meteo。也可以先用 Node.js 生成一份：`node scripts/build-data.mjs data.json`（这个文件已被 git 忽略）。

## 线上地址与更新

由 GitHub Actions 部署到 GitHub Pages（`.github/workflows/pages.yml`）。

修改文件后提交并推送，GitHub Actions 会重新获取数据并部署，约 2 分钟后线上更新：

```bash
git add -A && git commit -m "update" && git push
```

## 数据怎么到达浏览器

Open-Meteo 免费接口按 IP 限流：每分钟约 600 次、每小时 5,000 次、每天 10,000 次，变量多的请求按多次计算。完整下载一次全海岸数据（58 个地点 + 142 个远海采样点 × 4 个模型）大约就用掉一分钟的额度。如果每个访客都直接调用，很容易被限流（HTTP 429），或者因为排队太慢而超时。

所以：

1. **GitHub Actions 每小时运行一次**（`.github/workflows/pages.yml`）。它用 `scripts/build-data.mjs` 调用和网页完全相同的 `fetchAll()`，把结果写成 `data.json`，和网站一起部署到 Pages。
2. 浏览器先读本机缓存（30 分钟内有效），再读 `data.json`（2.5 小时内有效）。都不可用时才直接调用 Open-Meteo：每批 60 个点，最多同时 4 个请求，超时 45 秒，失败自动重试 2 次，遇到 429 会等待 20–40 秒再试。
3. 某一批请求失败时，只有对应地点显示“数据不足”。全部失败时，显示 12 小时内最后一次成功的数据，并明确标出是多久以前的；页面 1 分钟后会自动重试。

注意：GitHub 会在仓库连续 60 天没有提交后暂停定时任务。如果暂停了，到仓库的 Actions 页面重新启用即可，网页这时会自动退回到直接调用 Open-Meteo。

## 中英双语

- **界面和说明文字可以切换语言**：右上角的 **EN / 中文** 按钮。第一次访问时，语言跟随浏览器设置（中文系统显示中文，其他显示英文）。之后会记住访客的选择。
- **链接可以带语言**：`?lang=en` 或 `?lang=zh`。切换语言后，地址栏会自动带上这个参数，分享出去的链接对方打开就是同一种语言。
- **地名始终中英双语显示**：当前语言的名字在前，另一种语言的名字在后，或者显示在下一行。
- **所有文字都集中在 `i18n.js`**，中文和英文并排写。模型（`model.js`）和数据（`data.js`、`data.json`）不包含任何界面文字，只输出“文字编号 + 数字”，由页面按当前语言显示。所以切换语言不会重新获取数据，云端数据也只需要一份。
- **改文字时，中英两份都要改。** `tests.html` 会自动检查：两种语言的条目是否一一对应、占位符是否一致、页面和模型用到的每个编号是否都存在，以及有没有多余的条目。

## 访问统计

网站用 [GoatCounter](https://www.goatcounter.com/)（后台：https://runwang06.goatcounter.com）统计匿名访问次数，用来了解实际有多少人在用。不用 Cookie、不需要账号、不收集位置和任何个人信息；GoatCounter 不存 IP。每次访问只记录页面路径、来源网址、浏览器/系统、屏幕尺寸，以及由 IP 推断的国家。页面底部和“方法与局限”弹窗里都有中英文说明。`vendor/goatcounter/count.js` 是 GoatCounter 官方脚本（ISC 许可），和 Leaflet 一样放在本仓库里。`localhost` 上的访问不计数。

## 数据来源

- **天气，4 个模型**（Open-Meteo `/v1/forecast`）：HRRR 3 km、ECMWF IFS 0.25°、GFS 0.25°、ICON。最初还用了 GEM，后来去掉了：Open-Meteo 提供的 GEM 中、高云在所有地点、所有时刻都是 0，即使它的总云量不是 0。作为保险，现在如果某个模型的中高云几乎一直是 0、而其他多数模型明显有云，会被自动排除，并在页面上注明。变量包括低/中/高云量、能见度、2 m 温度与湿度、925 hPa 温度、降水。
- **海洋层垂直结构**（HRRR，GFS 作后备）：1000–900 hPa 各气压层云量、边界层高度。
- **空气质量**（CAMS global）：550 nm 气溶胶光学厚度（AOD）、PM2.5、沙尘。

## 和 San Diego 版相比，方法上改了什么

旧版用单点数据和一个综合公式。推广到整条海岸时，有三个问题必须单独处理：

1. **日落方向的光路。** 晚霞的光是太阳从地平线下方照到云底的。所以真正关键的是太阳方向 75–250 km 远海有没有低云堤，而不只是头顶有没有云。新版沿每个地点的日落方位角，在 25/75/150/250 km 处采样云量：近处的点算“画布”，远处的点算“光路”。远海点按距离对齐到 0.1°、0.25°、0.5° 的网格去重（58 个地点 → 142 个采样点）。
2. **全球模式会漏掉海洋层。** 实测 2026-10-07 的 SF Ocean Beach：HRRR 给出 100% 低云，四个全球模式都是 0%，而 925 hPa 比地面暖 13 °C，是典型的海洋层逆温。因此新版：(a) 用“逆温强度 × 近地面湿度”构造海雾启发式，修正每个模型的低云；(b) 判断海雾风险时 HRRR 权重更高（今天 50%，明天 30%）。
3. **地区与地形差异。** 每个地点用自己的坐标和海拔，并标注开阔海平线的扇区。圣克鲁兹、圣塔芭芭拉、马里布朝南，夏季太阳会落到陆地后面。海拔 ≥ 100 m 的观景点，如果高于由 HRRR 气压层云量估算的海洋层顶，会标为“雾上”，有机会看到云海晚霞。每个气候区有自己的逐月海雾频率和晚霞基准概率。

## 评分

每个模型分别计算：

```
score = 100 × 画布 × 光路 × 本地遮挡 × 空气透明度 × 海平线
```

- **画布**：中高云覆盖 cv = 1 − (1−high)(1−mid)，按观景点 0.35、25 km 0.4、75 km 0.25 加权。cv = 0 时为 0.22（干净的金色落日），45–72% 时为 1，100% 时为 0.55。
- **光路**：75/150/250 km 处 `low×0.8 + mid×0.3` 的加权平均，记作 block；光路 = 1 − 1.15 × block。
- **本地遮挡**：b = 0.8 × 有效低云 + 0.2 × 25 km 低云；本地 = 1 − 0.92 × b^1.6，再乘能见度与降水折减。如果处在雾上，本地 = 0.97，画布至少 0.45。
- **空气透明度**：AOD ≤ 0.15 时为 1，之后逐渐下降，最低 0.3；缺数据时用 0.88 并给出提示。
- **海平线**：日落方位在开阔海面扇区内为 1，否则 0.88。

**观赏评分** = 各模型评分的加权平均。权重：今天 HRRR 0.35 / ECMWF 0.27 / GFS 和 ICON 各 0.19；明天 HRRR 0.22 / ECMWF 0.32 / GFS 和 ICON 各 0.23。

**发生概率** = P(评分 ≥ 55)。每个模型贡献 sigmoid((s−55)/7)，加权后再向该地区、该月份的基准概率收缩，收缩程度按时效和可用模型数调整（今天保留 85%，明天保留 72%）。这个概率**尚未用观测校准**，适合横向比较，不应当作真实频率。

**置信度** 综合以下因素：模型分歧、可用模型数、时效、HRRR 是否可用、AOD 或光路数据是否缺失，以及海雾是否处在 30–70% 的临界区间（雾线进退最难预报）。

**最佳时段**：中高云很少时，看日落前 15 分钟到日落后 5 分钟；以高云为主时，看日落后 3–25 分钟；以中云为主时，看日落前 5 分钟到日落后 15 分钟。建议提前 25 分钟到达，需要上山的地点提前 45 分钟。

## 已知局限与后续方向

- 网格云量看不出云的纹理和破碎程度。下一步可以接入 GOES-West 卫星实况，用于临近预报。
- 海平线扇区和海拔是人工标注的近似值，没有做 DEM 视线计算。
- 海洋层顶在气压层分辨率下很粗（约 200 m 一层）；薄雾层会退回到边界层高度来估算。
- 概率需要校准：可以收集用户的“实际看到了吗”反馈，或者用历史卫星图做回测。
